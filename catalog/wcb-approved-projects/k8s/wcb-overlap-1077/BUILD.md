# wcb-approved-projects: overlap hex rebuild (#1077)

The 2026 hex was built centre-in-polygon: 332 of 3,915 projects (median 3,700 m², $86.9M
of WCB funding) contain no res-10 cell centre and had no rows. This rebuild uses
`--polyfill overlap` (cng-datasets 0.21.0): every project gets each res-10 cell it
touches, with `cover_frac`. Resolution unchanged: native 10, parents 9, 8, 0.

Generated by the command in `configmap.yaml`. Only the hex steps are kept. **Do not
re-run convert**: it rewrites the flat in place and renumbers `_cng_fid`, which the hex,
the PMTiles and the apps key on (see `catalog/high-seas/k8s/hydrothermal-vents/BUILD.md`).
The convert, pmtiles, setup-bucket and orchestrator manifests were deleted for that reason.

Apply in order, in `geo-workflows`:

1. `wcb-approved-projects-plan.yaml`
2. `wcb-approved-projects-hex.yaml`
3. `wcb-approved-projects-repartition.yaml`. The overlap footprint contains the old one, so
   every old `h0=` partition is rewritten. Confirm that no object under `hex/` predates the run.
4. `wcb-approved-projects-checksums.yaml`
5. the configmap from `set_overlap_stac.py`, then `wcb-publish-stac-1077.yaml`

Check (MCP): every flat `_cng_fid` appears in the hex (expect 3,915), and no orphans.
