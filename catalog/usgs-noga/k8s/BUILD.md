# USGS NOGA Assessment Units — build notes

Issue: [#700](https://github.com/boettiger-lab/data-workflows/issues/700).
Bucket `public-usgs`, dataset `noga-assessment-units`, namespace `geo-workflows`.

## What the source actually looks like

USGS publishes the national assessment one province or formation release at a time, in the
ScienceBase community
[59cab03de4b017cf314094df](https://www.sciencebase.gov/catalog/item/59cab03de4b017cf314094df).
Counted 2026-09-21: 187 children, 98 assessment-unit boundary releases, **57 United States**
and 41 non-US. There is no national compilation upstream.

Four things that are not obvious from one example release, each of which the build handles:

| | |
|---|---|
| **Results tables are recent** | Only **15 of 57** US releases ship `Tbl_FS_Results.csv`. Releases from 2018-2022 ship the AU boundaries plus per-AU assessment *input* forms (PDF/XLSX) and no results table, so their volume columns are null. |
| **11 releases serve no shapefile bytes** | ScienceBase's newer `CloudShapefileFacet`. `manager/download/<id>` returns the manager single-page app (4 KB of HTML for every part) and the item-level zip lists the same parts at length 0. Geometry comes from the ScienceBase GeoServer WFS GeoJSON export of the same layer. |
| **One release has no shapefile at all** | `5d1ce2fde4b0941bde64c542` (NanushukTorokAUs, 2020) publishes Esri JSON, GML and a file geodatabase. Read through GDAL's `ESRIJSON` driver. |
| **CRS and field hygiene** | Sources are EPSG:4269 (NAD83), some carry a constant Z, string fields carry trailing newlines (`"North America\n"`), and a few releases type the code columns as numbers. All normalised in the preprocess step. |

The release manifest is the edition record — a merged compilation has no upstream edition, so the
published collection carries **no version number**. `../manifest.json` is pinned and regenerated by
`../build-manifest.py`.

## Pipeline

```bash
# 1. stage raw + merge (57 releases -> one WGS84 GeoPackage)
kubectl -n geo-workflows create configmap noga-preprocess \
  --from-file=noga-preprocess.py=catalog/usgs-noga/k8s/noga-preprocess.py \
  --from-file=manifest.json=catalog/usgs-noga/manifest.json \
  -o yaml --dry-run=client | kubectl apply -n geo-workflows -f -
kubectl apply -n geo-workflows -f catalog/usgs-noga/k8s/noga-preprocess.yaml

# 2. convert / hex / pmtiles / repartition
kubectl apply -n geo-workflows -f catalog/usgs-noga/k8s/noga-assessment-units/configmap.yaml \
                               -f catalog/usgs-noga/k8s/noga-assessment-units/workflow.yaml
```

The build ran the steps individually (convert, then hex + pmtiles, then repartition) so the hex
chunking could be sized against measured polygon areas.

### Hex chunking is hand-tuned

`cng-datasets` floors `chunk_size` at 1000 features for small datasets, which would put all 240
assessment units in a single pod. Measured footprints run from a single field to **366,000 km²**,
about **12M H3 resolution 8 cells** in total, so `noga-assessment-units-hex.yaml` and the matching
block in `configmap.yaml` are edited to `--chunk-size 4`, `completions: 60`, `parallelism: 50`.
Regenerating the workflow with `cng-datasets workflow` resets this — reapply the edit.

Native resolution **8**, parents **`0`** (issue #700). AU boundaries are basin-scale interpretive
lines, so a finer resolution would assert precision the source does not have; resolution 8 is the
catalog's common join key, so this dataset carries `h8` natively.

`ST_Area_Spheroid` returns NaN for 220 of the 240 polygons, so footprint areas above are planar
degrees² scaled by `cos(latitude)`. They are used only for sizing the hex job.

## Traps for whoever reads this next

- **Null is never zero.** A blank `OIL_*` on a gas unit means oil was not assessed; a blank on a
  pre-2023 unit means the release published no results table at all.
- **Only the mean is additive.** `F95`, `F50` and `F5` are fractiles of one unit's probability
  distribution. Summing or area-weighting them across units is meaningless.
- **Units overlap and stack.** Conventional and continuous units and different Total Petroleum
  Systems cover the same ground, so dedup by `ASSESSCODE` before any `SUM`, on the flat parquet
  and on the hex.
- **`ASSESSCODE` is reused** when a province is reassessed. The published layer keeps the newest
  release of each code; the dropped codes are listed per release as `superseded_assesscodes` in
  `s3://public-usgs/raw/noga-assessment-units/build-report.json`.
